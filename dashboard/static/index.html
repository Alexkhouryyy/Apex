Compatibility
General plugins can register tools, pre/post tool hooks, slash commands and bundled skills. Apex also supports its own memory and context provider contracts. Plugins that depend on Hermes internals, platform/CLI/desktop APIs, privileged overrides or missing dependencies need adaptation. Python dependencies are checked, never silently installed. Native plugins are trusted code, not sandboxed.

Extend Apex
  1. Repositories: paste a public GitHub URL and inspect its pinned revision.
  2. Preview a discovered skill and read its files, dependencies and license.
  3. Plugins: review a native package, install disabled, configure it and enable it. Manage tools, hooks, commands, provider selection, updates and rollback here.
  4. Configure external tools in MCP or Apps.
  5. Skills: describe a missing capability, or select a skill to improve. Inspect generated changes in Approvals before activation.
Operate Apex
System & updates shows checkout readiness and update results. Settings & keys manages configuration. Sessions replays previous turns; Logs shows live events. Pairing manages device access.
Repository compatibility
Apex supports its documented plugin API and a subset of Hermes tool, command and hook conventions. Hermes-specific provider classes, desktop widgets, channels and other unsupported APIs require adapters. Plugin review reports declared dependencies and compatibility issues before activation.
